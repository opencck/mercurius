# hermes-antigravity-subscription — модели Antigravity по подписке через официальный CLI agy

Формат ссылок на код в этом конспекте: `<файл>:L<от>-L<до> (имя)` — это сокращение от
`references/hermes-antigravity-subscription/<файл>@6e46b46:L<от>-L<до> (имя)`.
В коде Меркурия ссылка пишется полностью, с префиксом `ref:`. Номера строк сверены с файлами коммита `6e46b46`.
Слова авторов: «worker» — долгоживущий процесс `agy` одной беседы; «oneshot» — процесс `agy` на один запрос;
«full send» — отправка всей истории одним запросом; «delta» — отправка только новых сообщений; «native tool» —
встроенный инструмент самого `agy`; «host» — Hermes.
Плагин рассчитан на `agy` 1.5.15–1.5.16; часть наблюдений в комментариях сделана на 1.2.x — версия указана у каждого
такого факта. Что прочитано не полностью и что по коду подтвердить не удалось — в разделе 15.

## 1. Кратко

Плагин — провайдер моделей для Hermes Agent (`kind: model-provider`, версия `1.0.35`, MIT; `plugin.yaml:L1-L7`).
Он даёт агенту модели Gemini, Claude и gpt-oss по подписке Google Antigravity, запуская локальный неизменённый
бинарник `agy` дочерним процессом в режиме `--input-format stream-json --output-format stream-json`
(`AGENTS.md:L9`, `README.md:L11-L13`). На беседу живёт один процесс `agy`; история хранится в самом `agy`, плагин
шлёт только новые сообщения, а после перезапуска процесса продолжает беседу флагом `--conversation <id>`
(`client.py:L1036-L1130`, `README.md:L57`). Инструменты хоста модели показываются текстом: модель пишет блоки
`<tool_call>{…}</tool_call>`, плагин разбирает их в вызовы функций формата OpenAI, исполняет их Hermes
(`README.md:L21`, `prompt.py:L558-L577`). Встроенные инструменты `agy` не разрешены: флага
`--dangerously-skip-permissions` нет, а на событие встроенного инструмента плагин убивает процесс; исключение —
чтение медиафайла через `read_file` (`README.md:L25`, `stream.py:L1242-L1274`). `agy` работает в собственном `HOME`
во временном каталоге, куда плагин линкует файл входа пользователя (`process.py:L844-L899`). Собственных учётных
данных у плагина нет, содержимое файла входа он не читает (`process.py:L754-L779`).

## 3. Устройство: процесс `agy` на беседу

- **Клиент — фасад OpenAI.** `AntigravityClient` отдаёт `chat.completions.create`; под ним — процесс `agy`
  (`client.py:L435-L496`). Клиент создаёт временный каталог `hermes_agy_*`, он же рабочий каталог процесса
  (`client.py:L481-L485`); локальные `GEMINI.md` и `AGENTS.md` проекта туда не попадают (`README.md:L29`).
- **Worker.** Один на клиента, под замком `_worker_lock` (`client.py:L569`, `client.py:L1304`). Процесс
  переиспользуется, пока совпадают модель и уровень усилия; иначе убивается и запускается заново
  (`client.py:L1044-L1063`).
- **Продолжение или полная отправка.** Если новые сообщения строго продолжают запомненную историю
  (`prompt.py:L1448-L1462`), в stdin уходит только хвост — delta; иначе процесс и базы бесед убираются и история
  отправляется целиком новому процессу (`client.py:L1324-L1362`). Предыдущий ответ ассистента, который `agy` уже
  держит у себя, из delta выбрасывается (`client.py:L151-L201`, `client.py:L1333-L1335`).
- **Идентификатор беседы** приходит в событиях `agy` (`conversation_id`) и запоминается
  (`stream.py:L1223-L1231`, `client.py:L807-L810`). Процесс, убитый по простою, из-за новых прав на медиа или после
  сбоя входа, поднимается с `--conversation <id>` (`client.py:L1072-L1073`, `client.py:L942-L951`).
- **Где лежит беседа.** Базы — `<HOME>/.gemini/antigravity-cli/conversations/*.db*`; при сбросе беседы плагин их
  удаляет (`client.py:L877-L884`). След сессии на диске — около 14 МБ (базы и журналы; `README.md:L178`).
- **Счётчики токенов накопительные.** Долгоживущий процесс (`agy` 1.2.10+) сообщает расход за всю сессию, поэтому
  расход хода — разность с предыдущим снимком (`stream.py:L207-L240`). После `--conversation` счётчики продолжаются
  с суммы сессии; без переноса снимка первый ход сообщал 201 502 токена при контексте 67 457
  (`client.py:L560-L568`). Поля: `input_tokens`, `output_tokens`, `cache_read_tokens`; `total_tokens` у `agy` может
  не включать чтение кеша (`stream.py:L184-L204`).
- **Простой.** Процесс без завершённого хода убивается через 900 с (`ANTIGRAVITY_WORKER_IDLE_SECONDS`), беседа
  сохраняется для продолжения (`client.py:L237`, `client.py:L920-L953`). Процесс весит около 200 МБ RSS
  (`client.py:L230-L236`); до ввода срока жизни при запуске намеряли 86 брошенных процессов на 15,3 ГБ
  (`client.py:L1117-L1129`).
- **Oneshot.** Если worker занят, запрос идёт отдельным процессом на один ход: весь промпт в stdin, затем stdin
  закрывается (`client.py:L1173-L1259`, `client.py:L1485-L1496`). Так обслуживаются параллельные субагенты
  (`README.md:L27`).
- **Сроки.** Срок хода — бюджет чтения из таймаута Hermes, по умолчанию 300 с (`client.py:L127`,
  `client.py:L1287-L1296`). Тишина в stdout 300 с (`ANTIGRAVITY_STREAM_STALL_SECONDS`) — процесс убивается; здоровый
  ход `claude-sonnet-4-6` на `agy` 1.5.16 молчал до первой строки 115 с (`stream.py:L292-L299`,
  `stream.py:L1143-L1168`).
- **Параллельные сессии одной учётной записи.** Вторая одновременная сессия может получить 503 «No capacity
  available», пока не закончится ход первой (`README.md:L180`).

## 4. Окружение процесса `agy`

Собирает `build_child_env` (`process.py:L1029-L1056`). Порядок: окружение родителя за вычетом похожего на секреты,
затем правки.

| Переменная | Что делает плагин | Зачем / что это говорит об `agy` | Где |
|------------|-------------------|----------------------------------|-----|
| `HOME` | Ставит на изолированный каталог `<cwd>/home` | `agy` держит состояние в `$HOME/.gemini/…`; так сессии, индекс бесед и память пользователя не затрагиваются | `process.py:L1035-L1036`, `README.md:L164` |
| `USERPROFILE`, `HOMEPATH` | Ставит туда же | `agy` написан на Go: `os.UserHomeDir()` на Windows читает `USERPROFILE`, затем `HOMEDRIVE`+`HOMEPATH` | `process.py:L1037-L1040` |
| `AGY_CLI_DISABLE_AUTO_UPDATE` | `setdefault("true")` — значение родителя важнее | У `agy` есть фоновое обновление (`agy --bg-updater`); на Windows оно открывает консоль | `process.py:L1041-L1043`, `README.md:L28` |
| `AGY_CLI_MODEL_API_MAX_RETRIES` | Не ставит; только пропускает в строгом режиме | Имя переменной есть в базовом списке строгого режима — см. раздел 9 | `process.py:L964`, `README.md:L118` |
| `SSH_CONNECTION`, `SSH_CLIENT`, `SSH_TTY` | Убирает, только если нет файла входа и не Windows | Признаки SSH-сессии для `agy` — см. ниже | `process.py:L1045-L1053` |
| `SSH_AUTH_SOCK`, `GPG_AGENT_INFO` | Оставляет, хотя имя похоже на секрет | Нужны git по SSH | `process.py:L953` |
| `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` (оба регистра) | Ставит из `ANTIGRAVITY_PROXY`, если она задана; иначе наследуются | `agy` (Go) читает только пару `HTTP(S)_PROXY`; `ALL_PROXY` — для программ, которые запускает `agy` | `process.py:L1004-L1015` |
| `NO_PROXY`, `no_proxy` | При заданном прокси сливает оба регистра и добавляет `localhost`, `127.0.0.1`, `::1` | `agy` общается со своим локальным language server по loopback; этот трафик нельзя вести через прокси | `process.py:L1001`, `process.py:L1016-L1026` |
| `DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR` | Не трогает (в шаблон секретов не входят, в строгом списке есть) | Через D-Bus `agy` достаёт вход из связки ключей Linux | `process.py:L951-L952`, `process.py:L960-L961` |

**Вычёркивание секретов — по имени.** По умолчанию из окружения родителя убираются переменные, чьё имя содержит
`TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `PASSPHRASE`, `API_KEY`, `ACCESS_KEY`, `PRIVATE_KEY`, `CREDENTIAL`, `AUTH`,
`WEBHOOK`, `DSN`, `COOKIE`, а также `DATABASE|DB|REDIS|MONGO*|POSTGRES*|MYSQL|AMQP|BROKER|CACHE` + `_URL|_URI`
(`process.py:L944-L949`, `process.py:L993-L998`). Авторы называют это эвристикой по имени: что лежит в переменной с
произвольным именем, она не знает (`process.py:L941-L943`, `README.md:L110`). `ANTIGRAVITY_ENV_PASSTHROUGH` —
список имён, которые оставить (`process.py:L985`).

**Строгий режим** (`ANTIGRAVITY_ENV_STRICT=1`) — белый список: `PATH`, `LANG`, `LANGUAGE`, `LC_*`, `TZ`, `TERM`,
`TMPDIR`/`TEMP`/`TMP`, прокси в обоих регистрах, `SSL_CERT_FILE`, `SSL_CERT_DIR`, `SSH_AUTH_SOCK`,
`DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`, `SYSTEMROOT`, `WINDIR`, `COMSPEC`, `PATHEXT`,
`AGY_CLI_DISABLE_AUTO_UPDATE`, `AGY_CLI_MODEL_API_MAX_RETRIES` плюс `ANTIGRAVITY_ENV_ALLOWLIST` и
`ANTIGRAVITY_ENV_PASSTHROUGH` (`process.py:L955-L965`, `process.py:L986-L992`). Этот список — перечень того, с чем
`agy` у авторов работает; по умолчанию режим выключен (`README.md:L256`).

**Признаки SSH.** `agy` 1.2.16 считает сессию SSH-сессией по `SSH_CONNECTION`, `SSH_CLIENT` или `SSH_TTY` и тогда
принудительно хранит вход в файле; строка журнала — «Using file-based token storage because SSH session detected»
(`process.py:L1045-L1048`). Если вход лежит в связке ключей, а файла нет, `agy` под этими переменными не находит
входа, поэтому плагин их убирает (`process.py:L1051-L1053`, `README.md:L218-L223`). Про то, что по этим признакам
`agy` печатает ссылку входа вместо открытия браузера, в коде и README ничего нет — см. раздел 15.

**Другие переменные `AGY_CLI_*`** в репозитории не встречаются, кроме `AGY_CLI_PATH`: это переменная плагина с путём
к бинарнику, наряду с `ANTIGRAVITY_COMMAND` и `ANTIGRAVITY_CLI_PATH` (`process.py:L317-L323`).

## 5. Вход

**Где `agy` хранит вход.**

| Место | Когда | Где |
|-------|-------|-----|
| Файл `~/.gemini/antigravity-cli/jetski-standalone-oauth-token` | Нет связки ключей: headless, контейнер, SSH-сессия. Имя с `agy` 1.2 | `process.py:L25-L34`, `process.py:L367-L369` |
| Файл `~/.gemini/antigravity-cli/antigravity-oauth-token` | То же, `agy` 1.1. Версия 1.2 читает только новое имя, а старый файл не удаляет | `process.py:L25-L34` |
| Secret Service Linux: `service=gemini`, `username=antigravity` (go-keyring) | Есть сессионная шина D-Bus. Без шины `agy` пропускает связку и пишет файл | `process.py:L443-L453`, `process.py:L658-L668` |
| Связка ключей macOS: generic password, service `gemini`, account `antigravity` | macOS; в `cli.log` — «authenticated via keyring» (проверено на 1.2.11) | `process.py:L702-L707` |
| Диспетчер учётных данных Windows: цель `gemini:antigravity` | Windows | `process.py:L426-L440` |

- **Поиск файла.** Сначала `ANTIGRAVITY_CONFIG_DIR` (если задан — другие места не смотрятся), затем
  `$HOME/.gemini/antigravity-cli/`, затем `/root/.gemini/antigravity-cli/`; в каждом каталоге новое имя раньше
  старого (`process.py:L349-L379`).
- **Проверка входа** — файл существует и больше 10 байт, либо запись есть в связке ключей; содержимое не читается
  (`process.py:L754-L779`). Проверка идёт на каждый запрос, без кеша (`client.py:L1277-L1281`,
  `process.py:L689-L693`).
- **Что плагин делает с файлом.** В изолированном `HOME` создаётся `<HOME>/.gemini/antigravity-cli/<то же имя>` как
  символическая ссылка на настоящий файл; не вышло — жёсткая ссылка; не вышло — копия (`process.py:L844-L899`).
  Перед каждым запуском `agy` ссылка сверяется и при необходимости пересоздаётся (`process.py:L382-L423`,
  `client.py:L1065-L1069`, `client.py:L1204`). На macOS в изолированный `HOME` линкуется весь
  `~/Library/Keychains`: без этого `agy` отвечает «Authentication required» (`process.py:L902-L934`).
- **Обновление токена.** `agy` при обновлении записывает по настоящему пути новый файл, поэтому копия отстаёт, а
  ссылка — нет (`process.py:L408-L409`). Несколько процессов `agy` одной учётной записи обновляют один токен:
  последний обновивший выигрывает, проигравший пишет «You are not logged into Antigravity» / «error getting token
  source» и не выдаёт результата (`process.py:L385-L388`, `client.py:L141-L148`, `README.md:L180`). Плагин ловит эти
  строки в stderr при пустом ходе, пересоздаёт ссылку и повторяет ход один раз (`client.py:L1414-L1450`).
- **Уборка не трогает токен.** При удалении каталога ссылки не раскрываются, чтобы не менять права настоящего файла
  входа (`client.py:L358-L432`).
- **Команды входа и выхода.** Плагин вход не выполняет. Единственное указание — текст ошибки: запустить `agy` в
  терминале и войти учётной записью Google (`client.py:L1277-L1281`). Отдельной команды входа и команды выхода в
  репозитории нет — см. раздел 15.

## 6. Командная строка и протокол

**Запуск worker** (`client.py:L1071-L1091`):

```
agy --input-format stream-json --output-format stream-json --disable-slash-commands
    [--agent hermes-inference-backend] [--conversation <id>] [--model <id>] [--effort <уровень>]
```

- `--output-format stream-json --disable-slash-commands` — аргументы по умолчанию (`client.py:L476`,
  `__init__.py:L423`); дополнительные — из `ANTIGRAVITY_ARGS` (`__init__.py:L425`).
- Oneshot — без `--input-format stream-json`: промпт уходит в stdin простым текстом и stdin закрывается; при
  сегментации флаг добавляется (`client.py:L1190-L1198`, `client.py:L1224-L1232`).
- Процесс: stdin, stdout, stderr — каналы, UTF-8, построчная буферизация, рабочий каталог — временный, своя группа
  процессов (`client.py:L1079-L1091`). Stderr вычитывается отдельным потоком, хранится хвост 64 КиБ
  (`process.py:L238-L304`).
- Прочие вызовы: `agy models` (каталог, `models.py:L209-L215`), `agy --version` (`custom_agent.py:L103-L114`),
  `agy -p /usage --output-format json` (раздел 8).

**Ввод** — NDJSON, строка на сообщение (`client.py:L1364-L1368`):

```json
{"event": "user", "message": {"content": "<текст>"}}
```

Несколько таких строк подряд в один процесс — последовательные ходы одной беседы (`stream.py:L1004-L1007`).

**События stdout** — NDJSON; строки, не начинающиеся с `{`, пропускаются (`stream.py:L1207-L1216`):

| Событие | Поля, которые читает плагин | Где |
|---------|-----------------------------|-----|
| `init` | `conversation_id` (на верхнем уровне или в `init`) | `stream.py:L1223-L1231` |
| `step_update` | `step_update.text_delta`; `step_type` (`"tool"`), `tool_name`, `tool_info` (`{"name", "parameters": {"Path": …}}`); `usage`; `conversation_id` | `stream.py:L1233-L1279`, `stream.py:L127-L141` |
| `result` | `result.status` (`SUCCESS`, `ERROR`, встречались `CANCELLED` и пустой), `response`, `error`, `usage`, `conversation_id` | `stream.py:L1364-L1448` |

- Ответ `-p … --output-format json` — один объект с полями `conversation_id`, `status`, `response`,
  `duration_seconds`, `num_turns`, `usage` (образец: `tests/test_usage.py:L34-L41`).
- Успех хода — только `status == "SUCCESS"`, нет поля `error` и есть содержимое; результат без ответа со статусом
  `CANCELLED` или пустым наблюдался, когда у `agy` обрывался внутренний канал, а процесс выживал
  (`stream.py:L1420-L1447`). Конец потока без события `result` — всегда ошибка (`stream.py:L1589-L1617`).
- Текст рассуждений в stream-json не отдаётся, флага для этого у `agy` нет (`README.md:L82-L83`).
- `init` — рукопожатие, а не признак работы модели: отказ по квоте может прийти после него
  (`stream.py:L1217-L1222`).
- `agy`, отказавшийся запускаться, пишет причину в stderr и выходит с кодом 3 без события `result`
  (`stream.py:L1584-L1587`).

**Встроенные инструменты и свой агент.**

- Агент `agy` по умолчанию ставит свой системный промпт («you are Antigravity», инструменты `run_command`,
  `view_file`, …) перед текстом пользователя; часть моделей слушается его, а не протокола `<tool_call>`
  (`README.md:L87-L98`, `prompt.py:L559-L565`). Замер: тот же вопрос — 10 749 входных токенов и 15 инструментов у
  агента по умолчанию против 1 218 токенов у своего (`custom_agent.py:L14-L20`).
- Свой агент — Markdown-файл `<HOME>/.gemini/config/agents/hermes-inference-backend/agent.md` с шапкой:
  `excludeDefaultComponents: true`, `inheritMcp: false`, `subagent: false`, `mainAgent: true`, `tools: [read_file]`
  (`custom_agent.py:L62-L77`, `custom_agent.py:L126-L128`). `name` и `description` обязательны; ошибка типа в YAML —
  файл пропускается целиком; `agy` читает определение один раз, при запуске (`custom_agent.py:L60-L61`).
  `manage_task` `agy` добавляет сам (`custom_agent.py:L22-L24`).
- Используется с `agy` 1.5.16: `excludeDefaultComponents` появился в 1.2.1, поиск агентов для `--agent` в headless —
  в 1.2.11, но в 1.2 инструмент чтения назывался `view_file`, а неизвестное имя инструмента роняет запуск

  construct executor» (то же в stderr); после него плагин до конца процесса запускает агента по умолчанию

- В headless без разрешающих правил `agy` сам отказывает встроенным инструментам (`prompt.py:L559-L561`,
  `process.py:L54-L57`). Плагин дополнительно на первом же событии `step_type == "tool"` (кроме разрешённого чтения
  медиа) закрывает поток и убивает процесс (`stream.py:L1242-L1274`).

## 8. Квота подписки

- **Команда:** `agy -p /usage --output-format json`, изолированный `HOME`, таймаут 8 с (`usage.py:L250-L265`). В
  коде — `/usage`; строки `/quota` в репозитории нет (раздел 15). Запрос не тратит токены модели и ходы
  (`README.md:L318`).
- **Формат** (образец — `tests/test_usage.py:L34-L86`): объект с полем `command: {"name": "usage", "data":
  {"description", "groups": […]}}`. Плагин ищет первый вложенный словарь со списком `groups` на глубине до 15, чтобы
  пережить смену обёртки (`usage.py:L126-L145`).
- **Группа:** `name`, `description`, `buckets[]`. **Корзина:** `id` (`gemini-weekly`, `gemini-5h`, `3p-weekly`,
  `3p-5h`), `name` (может отсутствовать), `window` (`weekly` или `5h`), `remaining_fraction` (доля остатка, 0…1),
  `reset_time` (ISO 8601 с `Z`) (`usage.py:L205-L233`, `tests/test_usage.py:L50-L82`).
- **Группы и модели:**

  | Группа | Что в неё входит (поле `description`) | Где |
  |--------|----------------------------------------|-----|
  | `Gemini Models` | Gemini Flash, Gemini Pro | `tests/test_usage.py:L47-L49` |
  | `Claude and GPT models` | Claude Opus, Claude Sonnet, GPT-OSS | `tests/test_usage.py:L66-L68` |
  | `Gemini 4 Argon` | Отдельный недельный пул на платных тарифах Pro; на Ultra — часть общей корзины Gemini | `tests/test_usage.py:L89-L98`, `usage.py:L345-L349` |

  Связь «модель → группа» плагин не вычисляет: группы только показываются, а сведения о составе — в тексте
  `description` (`usage.py:L350-L374`).
- **Расчёт:** использовано = (1 − `remaining_fraction`) × 100% (`usage.py:L382`).
- **Кеш:** 60 с; обновление в один поток; при неудаче без явного запроса отдаётся старое значение
  (`usage.py:L50`, `usage.py:L287-L342`). Ненулевой код возврата, таймаут, отсутствие бинарника — `None` и запись в
  журнал (`usage.py:L266-L282`).
- Токены в ответе хода — не счётчик квоты подписки (`README.md:L33`).

## 9. Раннее обнаружение исчерпания квоты

- **Что делает сам `agy`.** На 429 он повторяет запрос до 8 раз с экспоненциальной задержкой (около 140 с) и ничего
  не пишет в stdout (`process.py:L1065-L1066`). Образец строки журнала (`tests/test_antigravity_plugin.py:L2536-L2540`):

  ```
  I0921 21:19:51.264799     299 run.go:395] Run: attempt 1 failed (RESOURCE_EXHAUSTED (code 429): Individual quota reached. Please upgrade your subscription to increase your limits. Resets in 1h49m22s.), retrying in 4s
  ```

- **`AGY_CLI_MODEL_API_MAX_RETRIES`.** Плагин эту переменную не выставляет и нигде не читает; она только внесена в
  базовый список строгого режима, то есть проходит к `agy`, если задана у родителя (`process.py:L964`,
  `README.md:L118`). Что она управляет числом повторов 429, следует из имени; в коде это не утверждается и не
  проверяется (раздел 15).
- **Где журнал:** `<HOME>/.gemini/antigravity-cli/log/cli-*.log`; берётся самый свежий по времени изменения, читаются
  последние 16 384 байта, строки просматриваются с конца (`process.py:L1074-L1099`). Файл старше начала хода (с
  запасом 2 с) не учитывается; сравнение идёт по настенным часам (`process.py:L1088-L1091`, `stream.py:L1087-L1091`).
- **Какие строки ищутся** (`process.py:L1099-L1121`):

  | Признак в строке | Что возвращается |
  |------------------|------------------|
  | `ai credits balance is too low`, `credits balance is too low`, `daily or billing cap` (без учёта регистра) | Строка целиком |
  | `RESOURCE_EXHAUSTED` вместе с `Individual quota reached`, или `quota exceeded`, или `code 429` | Текст от `RESOURCE_EXHAUSTED` до `), retrying in` |

- **Когда работает сторож.** Отдельный поток раз в 0,3 с, начиная с первой секунды хода и до первого события, отличного
  от `init`; найдя строку, убивает процесс, ход падает с «Antigravity model error: <строка>»
  (`stream.py:L1102-L1122`, `stream.py:L1182-L1188`, `stream.py:L1221-L1222`). Тот же поиск повторяется, если
  процесс вышел с ненулевым кодом без содержимого (`stream.py:L1579-L1582`, `stream.py:L1647-L1650`).

## 10. Классификация ошибок

Функция `_classify_antigravity_error` смотрит на текст ошибки без учёта регистра (`__init__.py:L268-L341`):

| Признак | Класс | Что делает Hermes | Где |
|---------|-------|-------------------|-----|
| Код ошибки `agy_native_tool_protocol` (второй подряд встроенный инструмент) | `incomplete_response` | Без повтора, переход на запасного провайдера | `__init__.py:L280-L287`, `stream.py:L55-L58` |
| `subscriber fell behind updates`, `stalled for 5s`, `empty result (status='success')`, `max_trajectory_tokens`, `max trajectory tokens` | `context_overflow` | Повтор со сжатием контекста | `__init__.py:L289-L304` |
| `exceeded the output token limit`, `previous response was cut off` | `server_error` | Повтор без сжатия | `__init__.py:L305-L310` |
| `ai credits balance is too low`, `credits balance is too low`, `daily or billing cap`, `billing cap` | `billing` | Без повтора, запасной провайдер | `__init__.py:L311-L325` |
| `verify your account to continue`, `appeal a terms of service block`, `terms of service block`, `terms of service violation` | `auth_permanent` | Без повтора и без запасного провайдера: пользователю показывается сообщение со ссылкой | `__init__.py:L326-L340`, `README.md:L31` |
| Всё остальное | не классифицируется (`None`) | Общие правила Hermes | `__init__.py:L341` |

Чего в классификаторе нет (обрабатывается в других местах или никак):

- **Квота (`RESOURCE_EXHAUSTED` / 429)** — отдельного класса нет. Ход падает с текстом строки журнала (раздел 9),
  дальше решает общий классификатор Hermes.
- **Нет входа** — до запуска `agy`: ошибка «Antigravity CLI is not authenticated…» (`client.py:L1277-L1281`). Во
  время хода — строки «not logged into antigravity» / «error getting token source» в stderr: один повтор
  (`client.py:L141-L148`, `client.py:L1414-L1450`). На macOS без связки ключей — ответ «Authentication required»
  (`process.py:L908-L909`).
- **Нет мощности** — 503 «No capacity available» упомянут только в README (`README.md:L180`); в коде строки нет.
- **Неверная модель** — признака в коде нет. Есть только отказ запускать агента: «unknown agent», «failed to
  construct executor» (`custom_agent.py:L82-L85`).
- **Зависание** — «agy silent for Ns … process terminated» (`stream.py:L1158-L1162`); если `agy` успел ответить,
  в его `error` стоит `interrupted` (`stream.py:L1565-L1571`).

## 11. Длинный ввод

- **Где `agy` режет.** `agy` 1.5.15, учётная запись Google AI Pro, `gemini-4-neon-low`: одно сообщение пользователя
  молча обрезается, остаётся начало, ошибки нет. Промпты в 295 тыс. и 826 тыс. символов (около 2,1 символа на токен)
  оба дали 102 525 входных токенов; 397 тыс. символов (около 1,5 символа на токен) — 135 143. Авторы выводят срез
  около 190 тыс. символов, а не по числу токенов, и оговаривают: это вывод из двух замеров, не подтверждённое правило
  (`prompt.py:L1246-L1251`). Ранее срез видели на ~75 800 входных токенах (`__init__.py:L44-L47`).
- **Что не режется.** Та же беседа принимает много таких сообщений подряд: три сообщения по ~56 тыс. токенов дали
  `input_tokens` 180 204, начало и конец каждого модель помнила (`prompt.py:L1251-L1254`). На Claude обрезки нет
  (`prompt.py:L1286-L1287`).
- **Бюджет части** — в «весе»: 1 за символ ASCII, 2 за остальные; 90 000 веса ≈ 60 тыс. токенов. Плотный числовой
  ASCII — около 1,5 символа на токен, CJK — около 1 (`prompt.py:L1258-L1263`, `prompt.py:L1274-L1278`). По
  умолчанию делятся только маршруты Gemini; `HERMES_ANTIGRAVITY_SEGMENT_WEIGHT` задаёт бюджет всем моделям, `0`
  выключает, минимум 4 000 (`prompt.py:L1281-L1302`).
- **Как делится.** Только полная отправка тяжелее бюджета. Блоки промпта и записи истории набиваются по порядку,
  разрез — на границе сообщения; сообщение тяжелее части режется по строкам с пометками продолжения, слишком длинная
  строка — по символам (`prompt.py:L1305-L1345`, `prompt.py:L1369-L1445`). Текущая задача и последние сообщения идут
  в последнюю часть (`prompt.py:L1420-L1425`).
- **Подтверждения.** Части 1…N−1 обёрнуты в «[CONTEXT PART i/N] … Reply with exactly: ACK»; последняя — «[CONTEXT
  PART N/N, FINAL] … Treat all N parts as ONE prompt» (`prompt.py:L1348-L1366`). Части идут последовательными ходами
  одного процесса: следующая пишется в stdin после события `result` предыдущей со статусом `SUCCESS`
  (`stream.py:L963-L1013`). Ответы `ACK` до Hermes не доходят; расход, который видит Hermes, — только последний
  вызов (`stream.py:L966-L968`). Срок чтения перезапускается на каждой части (`stream.py:L1368-L1373`).
- **Сбои.** Ошибка или статус не `SUCCESS` на части — отказ всего запроса (`stream.py:L973-L982`); встроенный
  инструмент во время части — отказ, ничего не исполнено (`stream.py:L919-L951`). При повторе после сбоя входа
  отправка начинается с первой части в новой беседе (`client.py:L1435-L1442`).
- **Цена:** каждая часть — лишний вызов модели, 8–10 с на `gemini-4-neon-low` (`README.md:L55`).
- **Другие приёмы сокращения:** старые результаты инструментов режутся до 300 символов, последние 8 остаются целыми,
  отдельный результат — не больше 20 тыс. символов; в сессии из 336 сообщений это сократило ввод с 600 КБ до 180 КБ
  (`README.md:L30`).

## 12. Медиа

- **Как пиксели попадают к модели.** В headless у `agy` один путь: в тексте хода стоит ссылка `[Image](/abs/path)`,
  `[Video](/abs/path)` или `[Audio](/abs/path)`; модель вызывает встроенный `read_file` (в `agy` 1.2 — `view_file`)
  по этому пути, и `agy` сам вкладывает файл в ход как медиаблок и отправляет в Google (`prompt.py:L72-L74`,
  `stream.py:L61-L65`, `README.md:L149`). Событие инструмента содержимого не несёт; ответ приходит следующими
  `text_delta` (`stream.py:L1247-L1250`).
- **Подсказка модели.** В промпт хода со ссылкой добавляется раздел «MEDIA VIEWING PROTOCOL»: прочитать файл родным
  `read_file` по точному пути один раз (`prompt.py:L579-L608`). Без него общий запрет встроенных инструментов
  запрещает и это чтение — модель отвечает, что не видит вложение (`prompt.py:L579-L585`).
- **Права `agy`.** Headless-режим отказывает `read_file`/`view_file`, пока в
  `<HOME>/.gemini/antigravity-cli/settings.json` нет явного правила на путь: `permissions.allow:
  ["read_file(<абс. путь>)", "view_file(<абс. путь>)"]`. Формат взят из подсказки в stderr самого `agy`: «a tool
  required the read_file permission that headless mode cannot prompt for» (`process.py:L52-L59`,
  `process.py:L79-L113`).
- **Файл настроек читается только при запуске.** Перезапись под живым процессом ничего не меняет
  (`client.py:L1103-L1106`). Поэтому на ход с новым медиа плагин дописывает правила и перезапускает процесс с
  `--conversation`; проверено: красная картинка на первом ходу, перезапуск, синяя на втором
  (`client.py:L1003-L1034`, `README.md:L158`). Правила копятся, чтобы продолженная беседа могла перечитать старое
  вложение (`process.py:L84-L86`).
- **Проверка события на стороне плагина.** Чтение пропускается, только если инструмент — `read_file` или
  `view_file` и каждый путь из `tool_info` либо упомянут в этом ходе как медиа, либо лежит под каталогами медиа
  Hermes и временным каталогом системы; иначе процесс убивается (`stream.py:L71-L95`, `stream.py:L163-L181`,
  `stream.py:L691-L706`).
- **Откуда берётся файл** (`prompt.py:L413-L549`): data URL (декодируется в кеш), `file://` и локальный путь
  (передаются как есть, по пути), http(s) (скачивается в кеш). Кеш — `<дом Hermes>/cache/agy_media`, имя — первые 16
  знаков SHA-256 плюс расширение (`prompt.py:L43-L44`, `prompt.py:L399`).
- **Пределы:** 25 МБ на скачивание и на data URL (`prompt.py:L53-L54`); таймаут скачивания 15 с
  (`prompt.py:L502`); только `image/*`, `video/*`, `audio/*`; локальный путь — только с известным расширением:
  изображения `.png .jpg .jpeg .gif .webp .bmp`, видео `.mp4 .mov .webm .mkv .avi .ogv`, аудио
  `.mp3 .wav .m4a .ogg .oga .flac .opus .aac` (`prompt.py:L47-L49`, `prompt.py:L419-L425`). Отклонённое медиа
  выбрасывается, а не превращается в текстовую ссылку (`README.md:L155`). Пределов самого `agy` на размер и число
  вложений в репозитории нет (раздел 15).
- **Скачивание:** только публичные адреса — loopback, частные, link-local, зарезервированные и multicast
  отклоняются, проверяется каждый адрес имени и каждый шаг перенаправления (`prompt.py:L262-L318`). Тело пишется в
  `.part` и переименовывается после прохождения предела (`prompt.py:L375-L410`).
- **Уборка:** при закрытии клиента удаляются только файлы из собственного кеша плагина, но не файлы пользователя
  (`prompt.py:L329-L353`, `client.py:L669-L688`).

## 13. Уборка процессов

- **Своя группа.** На POSIX процесс запускается с `start_new_session=True`, на Windows — с
  `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW` (`process.py:L128-L143`).
- **Смерть родителя (Linux).** В `preexec_fn` ставится `prctl(PR_SET_PDEATHSIG, SIGKILL)`, после чего проверяется,
  что родитель тот же, иначе процесс убивает себя — закрывает гонку между `fork` и `prctl`
  (`process.py:L146-L164`).
- **Список своих процессов.** Все запущенные процессы регистрируются, при выходе интерпретатора (`atexit`) живые
  завершаются (`process.py:L167-L197`).
- **Завершение.** `terminate()` и ожидание 2 с; не вышло — `killpg(SIGKILL)` по группе на POSIX,
  `taskkill /F /T /PID` на Windows, затем `wait(2)`, чтобы не оставить зомби: наблюдали `[agy] <defunct>`, живший
  33 минуты (`process.py:L200-L235`).
- **Сироты (Linux, `/proc`).** При создании клиента убиваются процессы, у которых в командной строке есть и
  `--input-format stream-json`, и `--disable-slash-commands`, а `HOME` из окружения содержит `/hermes_agy_` и этого
  каталога уже нет; сигнал — `SIGTERM` (`process.py:L782-L841`, `client.py:L487-L494`). Причина: сирота держит беседу
  открытой на общей учётной записи; 17-часовой сирота путал ходы других сессий (`README.md:L167`,
  `process.py:L785-L788`).
- **Брошенный ход.** Процесс, чей ход держит замок, но молчит дольше порога и потратил меньше 1 с процессорного
  времени с последней строки (`/proc/<pid>/stat`), убивается; брошенный процесс тратил 2,5 с процессора за 16 минут
  (`client.py:L239-L263`, `client.py:L968-L1001`).
- **Отмена.** `cancel()` убивает worker и все oneshot клиента; клиент после этого не используется
  (`client.py:L623-L652`).
- **Закрытие.** Сначала процессы, потом медиафайлы, потом каталог; удаление каталога повторяется до трёх раз (0,1 с
  и 0,25 с), затем принудительно: на Windows `agy` ещё держит `conversations/*.db` после возврата `taskkill`
  (`client.py:L310-L328`, `client.py:L654-L692`, `client.py:L732-L771`).
- **Пропавший каталог.** Если временный каталог удалён снаружи, он создаётся заново, беседа теряется, следующий ход —
  полная отправка (`client.py:L812-L833`).

## 14. Сеть

- **Хосты.** Адресов серверов Google или Antigravity в коде, README и манифесте нет: с сетью работает только сам
  `agy`. Встречаются лишь `github.com` и `raw.githubusercontent.com` (репозиторий плагина), значки `img.shields.io`,
  сайт Hermes и произвольные адреса медиа, которые скачивает плагин (`plugin.yaml:L7`, `README.md:L7-L9`,
  `prompt.py:L486-L502`).
- **Локальный трафик `agy`.** `agy` общается со своим language server по loopback (`process.py:L1016-L1017`).
- **Прокси.** `ANTIGRAVITY_PROXY` принимает URL вида `http://127.0.0.1:8080` или `socks5h://127.0.0.1:1080`
  (`README.md:L254`); `agy` (Go) читает только `HTTP_PROXY`/`HTTPS_PROXY` (`process.py:L1009-L1010`). Работает ли
  `agy` через SOCKS, в репозитории не проверено (раздел 15). Без `ANTIGRAVITY_PROXY` `agy` наследует прокси
  родителя; `SSL_CERT_FILE` и `SSL_CERT_DIR` проходят к `agy` в обоих режимах окружения (`process.py:L959`).
- **Обновление.** Фоновое обновление `agy` выключается переменной `AGY_CLI_DISABLE_AUTO_UPDATE=true`
  (`process.py:L1041-L1043`).
- **Скачивание медиа** делает сам плагин (`urllib`, заголовок `User-Agent: Hermes-Agent`), не `agy`
  (`prompt.py:L499-L502`).

  ссылку входа, в репозитории нет. Подтверждено только: по этим переменным `agy` 1.2.16 переходит на хранение входа в

- **Пределы `agy` на медиа** (размер, число вложений, форматы на его стороне) — в репозитории только пределы

### От чего в конструкции плагина Меркурий отступает

1. **Долгоживущий процесс и `--conversation`.** У плагина история живёт в `agy`, хост шлёт дельты. Отсюда почти вся
   его сложность: накопительные счётчики и перенос снимка, срок простоя и «брошенные» ходы, сироты, перезапуск ради
   прав на медиа, сверка префикса истории, базы бесед на диске, собственное сжатие `agy` за спиной хоста (разделы 3,
   7, 13). В Меркурии историей и сжатием владеет ядро; модуль — процесс на вызов без состояния между вызовами. Цена
   отступления: каждый вызов — полная отправка, поэтому обрезка длинного сообщения Gemini (раздел 11) касается нас на
   каждом ходе, а не только на первом; сегментация с `ACK` либо ограничение окна — отдельное решение после своей
   проверки порога.
2. **Ссылка файла входа в чужой `HOME`.** Плагин живёт в одном пользователе с интерактивным `agy` владельца и
   линкует его файл входа во временный `HOME`; отсюда же спор за токен между сессиями (раздел 5). У Меркурия вход
   принадлежит модулю: один постоянный каталог состояния в контейнере, вход выполняется в нём самом, ссылок на файлы
   вне контейнера нет, ядро файл не читает и не копирует.
3. **Вычёркивание переменных вместо белого списка.** По умолчанию плагин отдаёт `agy` всё окружение родителя минус
   имена, похожие на секреты; сами авторы называют это эвристикой и дают строгий режим как надёжный (раздел 4). У
   Меркурия окружение процесса `agy` собирается с нуля по белому списку; отправная точка — базовый список строгого
   режима (`process.py:L955-L965`) без связки ключей и Windows.

Что из плагина остаётся образцом при этих отступлениях: изолированный `HOME` и пустой рабочий каталог; свой агент
без промпта и инструментов `agy`; отказ от `--dangerously-skip-permissions` и остановка процесса на событии
встроенного инструмента; признак успеха только по положительным данным события `result`; сторож журнала для раннего
отказа по квоте и сторож тишины; своя группа процессов и `PR_SET_PDEATHSIG`; запрос квоты отдельной командой с
кешем.
