## 1. Кратко

`gemini-api` — один статически собранный бинарь без состояния: команда на входе, файл или текст на выходе
(`README.md:L10-L16`, `README.md:L33-L35`). Он ходит в Gemini Developer API по адресу
`https://generativelanguage.googleapis.com` (`internal/sdk/geminiapi.go:L36-L39`), версия API по умолчанию — `v1beta`
(`internal/cli/root.go:L200`). Вся генерация — через Interactions API: один `POST /{api_version}/interactions`
(`internal/sdk/agent.go:L912-L975 (Agent.Run)`, путь — `L937`, операция `CreateInteraction` — `L947`). Состояние
запроса читается `GET /{api_version}/interactions/{interactionsId}` (`internal/sdk/agent.go:L1311-L1371 (Agent.Status)`),
отмена — `POST …/cancel` (`L1606-L1664`), удаление — `DELETE` (`L1137-L1187`).

Клиент рассчитан на вызов другим агентом из shell: команды, флаги и схемы запросов описывают себя сами (`--help`,
`--usage`, `--schema`), есть проверка без сети (`--dry-run`), структурные ошибки и коды выхода
(`README.md:L155-L172`). Проект в бете, интерфейс может ломаться между релизами; авторы советуют закреплять версию
релиза (`README.md:L333-L334`). Pull request не принимают (`README.md:L20`).

Большая часть кода сгенерирована Speakeasy из OpenAPI-документа (`internal/sdk/geminiapi.go:L19`, пометка
`Code generated by Speakeasy` в заголовках файлов, например `internal/cli/auth.go:L15`). Вручную написан каталог
`internal/cli/custom/` (`internal/cli/custom/register.go:L18-L23`).

## 3. Вход и учётные данные

Способов два, и оба — учётные данные Gemini Developer API:

| Способ | Флаг | Переменная | Заголовок запроса |
|--------|------|------------|-------------------|
| Ключ API | `--api-key` | `GEMINI_API_KEY` | `x-goog-api-key` |
| OAuth-токен доступа | `--access-token` | `GEMINI_ACCESS_TOKEN` | `Authorization: Bearer …` |

- Флаги и их описания — `internal/cli/root.go:L193-L196`; схемы безопасности SDK —
  `internal/sdk/models/components/security.go:L20-L21`.
- Имя переменной окружения строится из префикса `GEMINI` и имени флага (`internal/cli/root.go:L91`,
  `internal/config/config.go:L161-L165 (GetEnvValue)`), поэтому `--access-token` читается из `GEMINI_ACCESS_TOKEN`,
  `--user-project` — из `GEMINI_USER_PROJECT`, `--api-version` — из `GEMINI_API_VERSION`.
- Порядок поиска: флаг → переменная окружения → связка ключей ОС → `~/.config/gemini-api/config.yaml`
  (`internal/client/client.go:L211-L249 (BuildGlobalSecurity)`, `internal/config/config.go:L355-L380`). При
  `--dry-run` связка ключей не читается (`internal/config/config.go:L365-L374`).
- Отправляется ровно один способ: явно заданный (флаг или переменная) побеждает сохранённый
  (`internal/client/client.go:L220-L247`). Если в запросе есть `Authorization`, заголовок `x-goog-api-key`
  удаляется (`internal/sdk/sdkinternal/hooks/request_contract.go:L107-L109`).
- С токеном доступа обычно нужен проект квоты: `--user-project` / `GEMINI_USER_PROJECT` уходит заголовком
  `x-goog-user-project` (`internal/cli/root.go:L204`, `internal/client/client.go:L270-L275`,
  `internal/sdk/sdkinternal/globals/globals.go:L29`, `internal/sdk/sdkinternal/hooks/request_contract.go:L104-L106`).
  Токену нужен scope `https://www.googleapis.com/auth/generative-language`
  (`internal/output/errortable.go:L39-L44`).
- Сам клиент токен не получает и не обновляет: `auth login` только сохраняет введённое значение
  (`internal/cli/auth.go:L114-L232 (runAuthLoginCmd)`, выбор из двух способов — `L153-L159`). Истёкший токен — ошибка
  `ACCESS_TOKEN_EXPIRED` с советом обновить его самому (`internal/output/errortable.go:L33-L38`).
- На сервере без связки ключей: `--no-keyring` или `GEMINI_NO_KEYRING` — секреты хранятся в файле настроек
  (`internal/cli/root.go:L197`, `L95-L101`). `auth logout` стирает сохранённое (`internal/cli/auth.go:L234-L276`).
- `whoami` показывает, откуда взят каждый параметр, значения замаскированы (`internal/cli/auth.go:L82-L98`).
- Перенаправления на другой хост или с заменой метода не выполняются, чтобы ключ не ушёл чужому серверу
  (`internal/client/client.go:L115-L131 (SameOriginRedirect)`).

### Почему это не подписка

- Входа по подписке Google AI Pro/Ultra в клиенте нет: в форме `auth login` два варианта — ключ API и OAuth-токен
  доступа (`internal/cli/auth.go:L153-L159`), в SDK — те же две схемы
  (`internal/sdk/models/components/security.go:L19-L22`). Ни OAuth-потока в браузере, ни обмена кода на токен, ни
  обновления токена в коде команд нет.
- Адрес один — `generativelanguage.googleapis.com` (`internal/sdk/geminiapi.go:L36-L39`); это Developer API с
  оплатой по проекту. Ошибки прямо говорят о биллинге и квотах проекта: `BILLING_DISABLED` («включите биллинг в
  проекте… бесплатный уровень может быть недоступен в вашем регионе»), `QUOTA_EXCEEDED`, `RATE_LIMIT_EXCEEDED`,
  `USER_PROJECT_DENIED` (`internal/output/errortable.go:L84-L89`, `L103-L114`, `L127-L132`).
- OAuth-токен здесь — другой способ назвать тот же платный проект: с ним расход записывается на проект из
  `x-goog-user-project` (`internal/output/errortable.go:L127-L132`). Скилл предупреждает о том же: выставленный
  `GEMINI_API_KEY` «оплачивается проектом, которому принадлежит» (`internal/cli/custom/skill/SKILL.md:L25`).
- Вывод: каждый вызов идёт по прайсу API или в бесплатный уровень проекта. Лимиты подписки Google AI Pro/Ultra
  этим клиентом не расходуются и получить их через него нельзя.

## 4. Команды

Общее для команд генерации: тело запроса можно передать целиком через `--body` (JSON, `@файл`, `@-`), флаги
сливаются с ним, повтор ключа — ошибка использования (`internal/cli/agent/intent_image.go:L55`). Заготовка команды
(модель, формат ответа) подмешивается в тело (`internal/cli/agent/intent_image.go:L132-L141`). Модель меняется
флагом `-m/--model`.

## 5. Режимы для агентов

### `--agent-mode`

- Флаг — `internal/cli/root.go:L180-L181`. Включается только флагом (`internal/output/agentmode.go:L35-L41
  (InitAgentMode)`); флаг разбирается заранее, чтобы действовать и при ошибке разбора команды (`L96-L134`).
- Ошибка печатается в stderr одним JSON-объектом (`internal/output/agentmode.go:L53-L58`,
  `internal/output/output.go:L606-L620`, `L785-L802`). Поля конверта: `error_type`, `exit_code`, `message`, `hints`,
  `error_reason` (если есть), `status_code` (если был ответ HTTP), плюс поля тела ответа API
  (`internal/output/output.go:L804-L840 (classifiedErrorEnvelope)`). Секреты в тексте ошибки маскируются
  (`L622-L633`, `cmd/gemini-api/main.go:L46`).
- stdout по умолчанию — компактный TOON, а не «только путь»: формат выбирается как флаг → настройка → TOON в режиме
  агента → `pretty` (`internal/flagutil/flags.go:L82-L93 (ResolveOutputFormat)`). Команды медиа в этом режиме
  печатают конверт (`path`, `kind`, `size_bytes`, `mime_type`, `response_id`, `status` —
  `internal/output/artifact.go:L198-L216`, `internal/output/output.go:L336-L372`); то же у `tts`, `analyze`,
  `transcribe` (`internal/cli/custom/porcelain.go:L134-L152`, `L169-L187`). Чтобы получить JSON, нужен явный
  `--output-format json`.
- Сообщения о ходе работы в stderr в этом режиме не печатаются: stderr остаётся для документа ошибки
  (`internal/cli/custom/porcelain.go:L127-L132`).
- Чтение stdin ограничено по времени, чтобы команда не зависла на открытом пустом канале
  (`internal/cli/root.go:L103`, `internal/cli/custom/register.go:L317-L333`).
- Интерактивные формы выключаются флагом `--no-interactive` (`internal/cli/root.go:L172`).

| Код | Значение | Когда |
|----:|----------|-------|
| 0 | Успех | — |
| 1 | Ошибка исполнения или API | Всё, что не попало в 2 и 3: лимиты, ошибки сервера, сети, неудачный исход генерации |
| 2 | Ошибка использования | `validation_error`: неверные флаги, тело запроса, ответы 400 и 422 |

### `--dry-run`

- Проверяет флаги и тело, показывает запрос и не делает сетевого вызова; связку ключей не читает
  (`internal/cli/root.go:L176`, `internal/config/config.go:L365-L374`).
- Запрос перехватывается на уровне HTTP-клиента и получает синтетический ответ 200

- Машинный режим (режим агента, `--jq`, формат `json`/`yaml`/`toon`): в stdout по одному JSON-объекту на запрос —

- Значения секретных заголовков и полей скрыты (`L79-L131`, `L150-L160`).
- Локальные команды (`auth login`, `auth logout`, `configure`, `install-skill`) при `--dry-run` ничего не меняют

## 6. Files API и предел инлайна

- Локальный файл по умолчанию уходит внутри запроса. Бюджет одного запроса — 20 МБ вместе с base64, из них 1 МБ
  оставлен под промпт и обвязку (`internal/cli/custom/media.go:L49-L58`). Бинарный файл считается по размеру в
  base64 (4/3 от исходного), текст — как есть (`L60-L67 (inlineCost)`). Отсюда «около 14 МБ медиа»
  (`L69-L71 (inlineLimitNote)`, `README.md:L219`).
- Проверка идёт трижды: по каждому файлу (`internal/cli/custom/media.go:L404-L441 (checkLocalFile)`), по сумме
  входов (`L489-L493`) и перед отправкой по размеру тела `CreateInteraction`
  (`internal/sdk/sdkinternal/hooks/request_contract.go:L30-L31`, `L119-L151 (enforceInteractionRequestSize)`).
  Превышение — ошибка использования (код 2) с подсказкой загрузить файл.
- `files upload <path>` — возобновляемая загрузка `POST upload/<версия>/files` с заголовками `X-Goog-Upload-*`,
  частями по 8 МБ (`internal/cli/custom/files_upload.go:L43-L49`, `L119`, `L165-L170`). В stdout — имя `files/<id>`.
  `--wait` ждёт готовности файла, срок — `--wait-timeout`, по умолчанию 5 минут (`L65-L67`).
- Срок хранения — 48 часов; сервис принимает до 2 ГБ на файл (50 МБ для PDF) и 20 ГБ на проект
  (`internal/cli/custom/files_upload.go:L52-L53`, `internal/sdk/geminiapi.go:L92`, `README.md:L141`).
- `files/<id>` принимают `analyze`, `transcribe`, `generate`, `image`, `video`, `agent run` (`README.md:L219`).

## 7. Классификация ошибок

Источник — `internal/output/classify.go:L178-L281 (Classify)`. Порядок: причина из тела ответа

| 403 без учётных данных в запросе | `authentication_error` | 3 | Нет |

## 11. Что это значит для Меркурия

**(а) Основа MCP `gemini-api`.** Инструменты медиа по ключу API — обёртка над бинарём.

- Вызов: `gemini-api <команда> … --agent-mode --output-format json --no-interactive`. Без явного формата режим
  агента печатает TOON (`internal/flagutil/flags.go:L82-L93`); с `json` в stdout один объект с `path`,
  `mime_type`, `size_bytes` (`internal/output/artifact.go:L198-L216`), в stderr при ошибке — JSON с `error_type`,
  `exit_code`, `message`, `hints` (`internal/output/output.go:L804-L840`).
- Ключ — только переменной `GEMINI_API_KEY` в окружении процесса, плюс `GEMINI_NO_KEYRING=true`: в контейнере
  связки ключей нет (`internal/cli/root.go:L95-L101`). Ключ в аргументах и в ответе инструмента не появляется.
- Кандидаты в инструменты: `image`, `tts`, `music`, `video` (с `--async` и `--resume`: долгая операция не держит
  вызов), `transcribe`, `analyze`, `files upload --wait`, `agent run --background` и `agent status` для
  Deep Research.
- Файлы писать через `--out` в рабочий каталог участника; путь из конверта возвращать агенту.
- Вход больше ~14 МБ — сначала `files upload`, затем `files/<id>`; файл живёт 48 часов (раздел 6).
- Ошибка с кодом выхода 3 — остановиться и сказать владельцу про ключ, не повторять; код 2 — ошибка вызова, её
  исправляет модель; код 1 — смотреть `error_type` (раздел 7).
- Описания инструментов брать из `--help` команд и встроенного скилла (раздел 10), сверяя модели с кодом.
- Установка — закреплённый тег релиза, архив `gemini-api_Linux_x86_64.tar.gz` или `…_arm64.tar.gz`, проверка
  sha256 по `checksums.txt` (раздел 9). Штатный `install.sh` суммы не проверяет, поэтому его не используем.
- Расход: каждый вызов платный по прайсу API; генерация видео, музыки и Deep Research — дорогие операции, им нужны
  лимиты и подтверждение на стороне Меркурия. Клиент расход не ограничивает.

**(б) Образец для своего кода.**

- Запросы к Gemini API: Interactions API одним `POST /v1beta/interactions`, заголовок `x-goog-api-key`, поток —
  `Accept: text/event-stream` при `"stream": true` (`internal/sdk/agent.go:L937`, `L975-L983`,
  `internal/sdk/sdkinternal/hooks/request_contract.go:L113-L115`, `L153-L174`). Точные тела запросов видны через
  `--dry-run --output-format json` и `--schema`.
- Классификация ошибок: порядок «причина из тела → код HTTP → тип без ответа», отдельные классы для выключенного
  биллинга и сервиса, разворачивание тела-массива (раздел 7).
- Повторы: коды 408, 429, 5xx, учёт `retry-after-ms` и `Retry-After`, отказ ждать дольше остатка срока, повтор
  обрыва соединения только для идемпотентных методов; создание генерации не повторяется (раздел 8). Для платных
  генераций это правильное умолчание: повтор `POST` может оплатить работу дважды.
- Защита секрета: отказ от перенаправления на другой хост и маскирование секретов в ошибках
  (`internal/client/client.go:L115-L167`, `cmd/gemini-api/main.go:L46`).

**(в) Транспортом подписки быть не может.** Клиент работает только с ключом API или OAuth-токеном Developer API и
платным проектом (раздел 3). Доступ по подписке Google AI Pro/Ultra через него не получить; для подписки нужен
другой транспорт.

## 12. Что не прочитано и что не подтверждено

Не прочитано или прочитано выборочно:
- `internal/cli/custom/envruntime/` и `environments_runtime.go` (свои окружения управляемых агентов),

- `tests/contract/` — только список файлов и один тест;
- `internal/cli/custom/media.go`, `tts.go`, `transcribe.go` — объявления команд и ключевые функции, не целиком.

Не подтверждено кодом:
- **`GEMINI_CLI_AGENT_MODE=1`.** README называет эту переменную (`README.md:L171`), но в коде её нет: режим
  включается только флагом (`internal/output/agentmode.go:L35-L41`). Контрактный тест проверяет, что переменные
  окружения `CLAUDECODE`, `CURSOR_AGENT`, `CODEX`, `FORCE_AGENT_MODE` режим не включают
  (`tests/contract/cli_contract_test.go:L2054-L2058`). Использовать флаг.
- **Код выхода `generate`, `agent run`, `agent status` при состояниях `failed` и `cancelled`.** Скилл говорит, что
  эти команды выходят с 0 и сообщают состояние в `.status` (`internal/cli/custom/skill/SKILL.md:L63`); аннотации
  команд помечают `failed` и `cancelled` как неудачу (`internal/cli/agent/intent_generate.go:L47`,
  `internal/cli/agent/status.go:L51`). Какое поведение у собранного бинаря — не проверено запуском.
- **Состояние `incomplete` у `image` и `music`.** Скилл говорит о коде 1 при «failed/incomplete»
  (`SKILL.md:L63`); в аннотациях `incomplete` и `budget_exceeded` — успех, для `video` — неудача
  (`internal/cli/agent/intent_image.go:L48`, `internal/cli/agent/intent_video.go:L50`). Не проверено запуском.
- **Алгоритм `checksums.txt`.** В `.goreleaser.yaml` задано только имя файла (`L53-L54`); sha256 — умолчание
  GoReleaser, в репозитории это не записано. Проверить по файлу релиза.
- **Наличие релиза и его тег.** В сабмодуле тегов нет; версия `0.5.0` взята из кода, существование релиза
  `v0.5.0` и состав его файлов не проверялись.
- **Цены, бесплатный уровень и лимиты.** В коде есть только тексты ошибок о биллинге и квотах; сами тарифы — в
  документации Google.
- **Модели и агенты в живом API.** Имена моделей и агентов взяты из встроенного каталога и подсказок флагов;
