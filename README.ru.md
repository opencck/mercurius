# Меркурий

[English](README.md) | **Русский**

Меркурий — автономный персональный агент. Он ставится на ваш сервер через Docker Compose, а общаетесь вы с ним через Telegram-бота. Он помогает с любой работой: поиск в интернете, работа с серверами по SSH, написание кода и ведение программных проектов, планирование, исследования и тестирование.

**Состояние:** работает на сервере владельца; готовы фазы разработки 0–5 (MVP и делегирование воркерам). Остальное в разработке; план — в [`ROADMAP.md`](ROADMAP.md).

## Что уже работает

- Telegram-бот (webhook или long polling): ответ по мере генерации, Markdown, разбиение длинных сообщений, файлы и кнопки.
- Агентский цикл с инструментами: HTTP-запросы, файлы и команды в контейнере-песочнице со своим пользователем и лимитами для каждого участника (PHP с Composer, Python, Node.js, Go). Лимиты ходов, токенов и времени — в коде; запуск переживает перезапуск.
- Необратимые действия (`git push`, `ssh`, отправка данных, HTTP кроме GET) ждут карточки подтверждения владельца; «Разрешать всегда» сохраняет разрешение на это действие и эту цель; `/permissions` — список и отзыв.
- Участники: незнакомец, написавший боту, ждёт решения владельца; у каждого участника свои инструменты и лимиты.
- Сжатие контекста: сначала обрезаются старые результаты инструментов, затем середина беседы пересказывается дешёвой моделью.
- Роли моделей (дешёвая, основная, сильная, медиа) выбираются по грубому классу первого запроса; модели любого провайдера (OpenRouter и OpenAI API); агент и владелец меняют роли с указанием причины.
- Трассы каждого запуска: шаги со временем, токенами и стоимостью; `/usage`, `/runs`, `/trace <номер>`; метрики Prometheus под токеном.
- Делегирование: агент делит задачу на части для воркеров с чистым контекстом, части только на чтение — параллельно, в общем бюджете токенов. Каждой части — модель по её потребностям (оценки 1–10 против индексов каталога, самая дешёвая подходящая, повтор на более сильной, если модель подвела); часть, где ошибка дорога, проверяет отдельный проверяющий. Долгая работа идёт в фоне, переживает перезапуск и приходит отчётом отдельным сообщением; `/delegation` показывает, как агент делит работу.

## В планах

Долговременная память; серверы по SSH, в том числе через VLESS; браузер; скиллы и MCP-серверы; задачи по расписанию и проекты; сеть экземпляров Меркурия по WebSocket.

## Как запустить

1. Клонировать с сабмодулями: `git clone git@github.com:opencck/mercurius.git && cd mercurius && git submodule update --init --depth 1 packages/llm packages/connectors packages/messenger`.
2. Скопировать `.env.example` в `.env` и заполнить: как минимум `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_ID` (ваш id в Telegram), `OPENROUTER_API_KEY` или `OPENAI_API_KEY` (достаточно одного), `POSTGRES_PASSWORD`, `SANDBOX_TOKEN`. Каждая переменная пояснена в файле.
3. `docker compose up -d --build`. Миграции базы применяются при старте.
4. Напишите боту. Команды: `/new`, `/stop`, `/permissions`, `/usage [дни]`, `/runs`, `/trace <номер>`, `/delegation [дни]`.

## Стек

PHP 8.2+, AMPHP v3 / Revolt, [`opencck/server`](https://github.com/opencck), PostgreSQL; модели — через OpenRouter и OpenAI API. В каждом репозитории — PHPUnit, PHPStan и Psalm (`composer check`).

## Репозитории

Компоненты, полезные вне Меркурия, живут в отдельных репозиториях и подключены сабмодулями в `packages/`:

| Репозиторий | Назначение |
|-------------|------------|
| [`mercurius-llm`](https://github.com/opencck/mercurius-llm) | Единый интерфейс вызова языковых моделей: сообщения, инструменты, потоковый ответ, учёт токенов и стоимости, ошибки и повторы. |
| [`mercurius-connectors`](https://github.com/opencck/mercurius-connectors) | Маршруты исходящих соединений как фабрика Amp `SocketConnector`: напрямую, HTTP CONNECT-прокси, SOCKS5, VLESS (через `amphp/vless`) и их цепочки. |
| [`mercurius-messenger`](https://github.com/opencck/mercurius-messenger) | Единый интерфейс канала сообщений с нормализованной моделью сообщения и адаптер Telegram Bot API (webhook и long polling). |

Пакеты в планах: `mercurius-command-policy` (классификация опасности команд и политика), `mercurius-memory` (долговременная память), `mercurius-browser-service` (Chrome за HTTP API), `mercurius-mcp-client` (клиент MCP), `mercurius-peer` (связь экземпляров Меркурия).
