# Песочница и инструменты файлов и команд (часть 2 фазы 3) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** агент читает и пишет файлы и выполняет команды в отдельном контейнере-песочнице — у каждого участника свой
каталог и свой пользователь Unix, с лимитами; большой результат инструмента уходит в файл, в контекст — превью и путь.

**Architecture:** сервис `sandbox` в compose запускает HTTP-исполнитель на amphp (`OpenCCK\Sandbox`, вход
`sandbox.php`) от root с минимумом прав. Каждая операция — команда или файловая — выполняется **от пользователя
участника** (`prlimit` → `setpriv` → `setsid bash -c`), поэтому границы каталогов держит ядро, а не проверки путей.
Ядро ходит к исполнителю через `HttpSandboxClient` (интерфейс `App\Agent\Sandbox\Sandbox`); четыре инструмента
работают поверх этого интерфейса; `ToolExecutor` выгружает большие результаты через него же.

**Tech Stack:** PHP 8.2, amphp/http-server (+router), amphp/process, amphp/http-client, util-linux (`prlimit`,
`setpriv`, `setsid`), Docker Compose. Тесты исполнителя, которым нужен Linux и root, — группа `sandbox`, запускаются
в контейнере песочницы на сервере.

**Spec:** [BRIEF.md → Песочница](../BRIEF.md#песочница), [→ Инструменты](../BRIEF.md#инструменты),
[→ Права участника](../BRIEF.md#права-участника). Подтверждения для команд наружу — часть 3, не здесь.

- Ссылки `ref:` на hermes — коммит `e96221f`, строки сверять по файлу; `spec:` — на якоря `BRIEF.md`.
- Лимиты контейнера из `.env`: `SANDBOX_CPUS=2`, `SANDBOX_MEMORY=2g`, `SANDBOX_PIDS=512`,
  `SANDBOX_WORKSPACE_LIMIT=5g` (решение владельца). Лимиты одной команды (новые переменные):
  `SANDBOX_COMMAND_CPU_SECONDS=600`, `SANDBOX_COMMAND_MEMORY=8g` (адресное пространство, см. Review Focus 4),
  `SANDBOX_CONCURRENT_COMMANDS=4`. `SANDBOX_TOKEN` — секрет только песочницы; `SANDBOX_URL=http://sandbox:9000`.
- Пользователь участника: имя `p<id>`, uid/gid `20000 + id`, домашний каталог `/workspace/p<id>`, права `0700`.

  моделей — часть 5), поэтому порог фиксированный; доля окна — в части 5.
- Вывод команды — окно «начало + конец» по 25 000 байт во время чтения; лишнее отбрасывается с пометкой
  «… пропущено N байт …».
- Песочница не подключена к сетям `internal` и `web`; переменные окружения ядра в неё не передаются.
- Коммиты — по `CLAUDE.md` (английский, через `watermarks-remover`, без `Co-Authored-By`), перед каждым
  `composer check` зелёный.

## Review Focus

1. **Побег по символической ссылке:** участник командой делает `ln -s /workspace/p2 x` или `ln -s /etc/shadow y`, затем
   `read_file x/…` — должен получить отказ ядра (операции идут от его uid, чужой каталог `0700`), а не содержимое.
   Тест — задача 3.
2. **Команда порождает фоновые процессы** (`sleep 1000 &`, `nohup`) и/или висит дольше таймаута — после таймаута
   или отмены в сессии команды не остаётся ни одного процесса. Тест — задача 3.
3. **Каталог переполнен** (`fallocate -l 6G big`) — следующая запись отклоняется с понятным текстом, команда
   выполняется (чтобы можно было удалить лишнее), результат команды предупреждает о превышении. Тест — задача 3.
4. **Тяжёлые инструменты** (`node`, `composer`, `python -m pip`) резервируют много виртуальной памяти — лимит
   адресного пространства 8 ГБ не должен ломать их запуск; настоящий потолок памяти — 2 ГБ контейнера.
   Проверка — задача 9 (`node -e 'console.log(1)'`, `composer --version` в песочнице).
5. **Песочница достаёт до хоста и локальной сети сервера** (адрес шлюза Docker, порты на `0.0.0.0` хоста) — запрос
   из песочницы к хосту и частным адресам отклоняется правилом `DOCKER-USER`; к внешнему интернету — проходит.
   Проверка — задача 9 (правило ставит владелец или с его разрешения).

### Task 3: Исполнение от пользователя участника (Linux)

**Files:**
- Create: `src/Sandbox/Users.php`, `src/Sandbox/CommandRunner.php`, `src/Sandbox/ProcessTree.php`,
  `src/Sandbox/Files.php`, `src/Sandbox/Usage.php`
- Test: `test/Sandbox/CommandRunnerTest.php`, `FilesTest.php` (группа `sandbox`: Linux, root, util-linux) —
  локально исключены, запускаются в контейнере песочницы (задача 5)

**Interfaces:**
- Consumes: `Workspace`, `OutputWindow`, `SandboxError`, `SandboxLimits`.
- Produces:
  - `Users::ensure(int $principalId): void` — `groupadd`/`useradd --uid/--gid 20000+id --no-create-home --home-dir
    /workspace/p<id> --shell /bin/bash p<id>` если нет в `getent`; каталог создаётся, `chown`, `chmod 0700`.
    Пользователи не переживают пересоздание контейнера — uid детерминирован, файлы на томе сохраняют владельца.
  - `CommandRunner::run(int $principalId, SandboxLimits $limits, string $command, string $cwd, int $timeoutSeconds,
    ?string $stdin, Cancellation $cancellation): CommandResult` — argv:
    `prlimit --nproc=P --cpu=C --as=M -- setpriv --reuid=U --regid=U --clear-groups -- env -i HOME=… PATH=/usr/local/go/bin:/usr/local/bin:/usr/bin:/bin LANG=C.UTF-8 setsid bash -c <command>`;
    `cwd` — уже разрешённый путь; вывод stdout и stderr — каждый через `OutputWindow`; таймаут или отмена →
    `ProcessTree::killSession()` и `timedOut`/`cancelled` в результате. Одновременных команд участника больше
    `concurrentCommands` → `SandboxError(429)`.
  - `CommandResult(int $exitCode, string $stdout, string $stderr, bool $timedOut, bool $cancelled, int $durationMs)`.
  - `ProcessTree::killSession(int $pid): void` — читает `/proc/*/stat`, находит сессию процесса-потомка `setsid`
    (первый потомок `$pid` с новым `sid`) и шлёт `SIGKILL` всем процессам этой сессии; так гибнут и фоновые
    (`&`, `nohup`). Отступление от hermes (`kill_live_foreground_processes`): у нас нет cgroup на команду —
    процессы, ушедшие в новую сессию сами (`setsid` внутри команды), не догоняются; записать одной фразой.
  - `Files` — все операции через `CommandRunner` от пользователя участника (права ядра держат границу):
    `read(int $principalId, string $path, int $startLine, int $maxLines): array{text: string, totalLines: int}` —
    `sed -n`/`wc -l`; `write(int $principalId, string $path, string $content): void` — `mkdir -p` + `cat >` из stdin;
    `replace(int $principalId, string $path, string $old, string $new): void` — `old` должен встретиться ровно один
    раз, иначе `SandboxError(409)` с числом вхождений; `list(int $principalId, string $path, int $depth): list<array{path: string, type: string, size: int}>` —
    `find -maxdepth N -printf`, не больше 500 записей.
  - `Usage::bytes(int $principalId): int` — `du -sb` от root.
- Квота: `Files::write`/`replace` проверяют `Usage + strlen(content) <= diskBytes` до записи (`SandboxError(413)`);
  `CommandRunner` после команды добавляет в результат `overQuota: bool`.
