# Экспорт и импорт агента — план (фаза Д14)

Временный файл: удаляется, когда итог перенесён в `BRIEF.md`.

**Цель:** владелец командой в личном чате получает зашифрованный архив агента и может поднять из него агента на
другом экземпляре; частичный импорт (память, скиллы) — через агентский цикл.

## Решения исполнителя (владелец может поправить)

- **Формат один с `bin/backup.sh`:** те же файлы с теми же именами — `db.dump` (`pg_dump -Fc`), `app.tar.gz`
  (`storage/app`), `workspace.tar.gz` (рабочие каталоги), `env`, `commit`. Экспорт — эти файлы в tar (простой, без сжатия поверх уже сжатых частей), зашифрованный
  паролем: `MRCX1` + соль + поток `sodium secretstream` (XChaCha20-Poly1305), ключ — Argon2id от пароля (В10:
  хранилище секретов и мастер-ключ входят — `env` содержит `SECRETS_KEY`).
- **Где собирается:** в контейнере приложения — `pg_dump` (клиент PostgreSQL 17 в образе приложения), `storage/app`
  смонтирован; рабочие каталоги отдаёт исполнитель песочницы (root) новым действием `archive` / `unarchive` под
  токеном песочницы. `env` — файл `.env` экземпляра монтируется в приложение только для чтения.
- **Пароль:** `/export` → бот просит пароль следующим сообщением; сообщение с паролем удаляется; пароль от 12 символов.
- **Размер:** архив кладётся в `storage/app/exports/`; если он меньше предела канала (50 МБ, с локальным сервером Bot
  API — 2 ГБ), уходит файлом в личный чат владельца; иначе владелец получает путь на сервере.
- **Полный импорт:** владелец присылает архив в личный чат и пишет `/import <пароль>`; карточка «Заменить агента
  этим архивом?»; по «Да» — сначала экспорт текущего состояния в `storage/app/exports/`, затем архив
  расшифровывается в `storage/app/import/pending/`, приложение завершается (compose перезапускает), при старте до
  миграций: `pg_restore` с пересозданием схемы, распаковка `app.tar.gz`, рабочие каталоги — через исполнитель.
  `env` из архива не применяется (сверка вручную, как у `restore.sh`), кроме `SECRETS_KEY` — без него хранилище
  секретов не прочитать: ключ кладётся в `storage/app/secrets.key`, приложение берёт его, если в `.env` пусто или он
  другой (`/doctor` предупреждает).
- **Частичный импорт:** инструмент `agent_import` (только владелец, карточка) с `part: memory|skills` и путём к
  архиву в песочнице: память — факты и ядро из дампа (`pg_restore --data-only -t …` во временную схему, затем
  вставка новых строк), скиллы — папки `.mercurius/skills` из `workspace.tar.gz`.

## Шаги

1. `ArchiveCrypto` (шифрование/расшифровка потоком, тесты) — `src/App/Export/`.
2. Сборщик архива `AgentExport` (дамп, файлы, рабочие каталоги через исполнитель) и действие исполнителя `archive`.
3. `/export` с паролем, удаление сообщения, отправка файла или путь.
4. Полный импорт: `/import`, карточка, копия, перезапуск, восстановление при старте; действие исполнителя `unarchive`.
5. Частичный импорт: `agent_import` для памяти и скиллов.
6. `BRIEF.md`, `self_info`, проверка: архив основного → тестовый экземпляр.
