# Сеть агентов (A2A v1.0), часть 1 — план

Спецификация: [BRIEF.md → Сеть агентов](../BRIEF.md#сеть-агентов), подраздел «Протокол: A2A v1.0».
Образец: `references/hermes-agent/plugins/platforms/a2a/` (`protocol.py`, `adapter.py`, `security.py`).

## Задачи

1. **Схема (миграция 28):** `peer_tokens` (участник-агент, хеш токена, отзыв), `a2a_tasks` (входящие: задача,
   сосед, контекст, `messageId` — уникально на соседа, состояние, запуск, итог), `peers` (исходящие: имя, адрес,
   имя секрета с токеном, карточка), `a2a_outgoing` (отправленные задачи: сосед, удалённый номер, чат, состояние,
   итог). `PrincipalRepository::createAgent`.
2. **Ведомый:** `GET /.well-known/agent-card.json`, `POST /a2a` (JSON-RPC: `SendMessage`/`message/send`,
   `GetTask`/`tasks/get`, `CancelTask`/`tasks/cancel`). Проверки по порядку: токен → частота (60/мин) → метод →
   идемпотентность → петля (свой экземпляр в `path`, глубина ≥ 3) → потолок ходов в контексте (5). Запуск под
   участником-агентом с его политикой; итог без секретов; `[INPUT_REQUIRED]`; сторож зависших задач.
   Подтверждения — карточкой своему владельцу (продолжение запуска — как у заданий, через `JobRuns`).
3. **Ведущий:** реестр соседей (`/peer add <имя> <url> <секрет>`), инструмент `peer_delegate` (отправить и вернуться),
   опрос открытых задач раз в 30 с, итог — в чат и в беседу как недоверенные данные с номером удалённой задачи.
4. **Команды владельца:** `/peers`, `/peer token <имя> [user|admin]` (токен показывается один раз), `/peer revoke <имя>`,
   `/peer add`, `/peer remove`.
5. **Проверка на сервере:** `mercurius` ↔ `mercurius-doorotar` ↔ `mercurius-rekryt`: задача, отказ по отозванному
   токену, обрыв цикла, повтор `messageId`.

Тесты — вперёд по каждой задаче; `composer check` перед каждым коммитом.
