# Трассировка и метрики — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** по идентификатору запуска видна цепочка шагов с токенами, стоимостью и временем; владелец получает сводку
расхода командой; Prometheus забирает метрики; в сохранённых трассах нет секретов.

**Architecture:** цикл и вспомогательные вызовы сообщают о шагах через интерфейс `AgentEvents`; подписчик `Tracer`
пишет `trace_spans` (шаги) и `trace_payloads` (полные запросы и ответы, замаскированные, со сроком хранения).
`TraceReports` строит ответы на `/usage`, `/runs`, `/trace`; `MetricsHandler` отдаёт `/metrics` из БД.

**Spec:** [BRIEF.md → Трассировка и метрики](../BRIEF.md#трассировка-и-метрики), события —
[Устройство приложения](../BRIEF.md#устройство-приложения-на-opencck). Опора — backendbytes (`runTraced`), hermes
`usage_pricing.py` (корзины и статус стоимости), skill-opencck (Prometheus-экспортёр).

## Global Constraints

- Виды шагов: `run`, `model`, `tool`, `approval`, `compaction`, `classification`; статусы `ok`, `error`, `cancelled`.
- Статус стоимости: `actual` (прислал провайдер), `estimated` (по ценам каталога), `unknown`.
- `TRACE_RETENTION_DAYS` — 14 (1..365); очистка `trace_payloads` раз в сутки; шаги и `llm_calls` не удаляются.
- `METRICS_TOKEN` пуст — `/metrics` отвечает 404; задан — без верного `Authorization: Bearer` 401.
- Ошибка записи трассы не влияет на запуск — только `error` в журнал.
- Секреты маскируются до записи (`SecretMasker::maskArgs` для запросов, `mask` для текста).
- Команды `/usage [дни]` (1..90, по умолчанию 7), `/runs`, `/trace <id>` — только владелец; длинный ответ (> 3500 символов) — файлом.

## Review Focus

1. Запись трассы падает (БД недоступна) — запуск идёт дальше. (Task 2, `testTraceFailureDoesNotBreakTheRun`.)
2. Ключ API или пароль в аргументах инструмента или в промпте — в `trace_payloads` его нет. (Task 2, `testPayloadsAreMasked`.)
3. `/metrics` без токена или с чужим — нет данных. (Task 4, `testMetricsNeedTheToken`.)
4. `/trace` чужого или несуществующего запуска, `/usage` от не-владельца — отказ без данных. (Task 3.)
5. Запуск, продолженный после перезапуска, — шаги дописываются к тому же запуску. (Task 2, `testResumedRunAddsToTheSameTrace`.)

- Миграция `0007_traces.sql`: `trace_spans`, `trace_payloads` (`span_id`, `request jsonb`, `response jsonb`, `created_at`),
  `llm_calls.run_id`.
- `TraceRepository`: `start(Span): int`, `finish(int $id, …)`, `payload(int $spanId, array $request, array $response)`,
  `purgePayloads(DateTimeImmutable $before): int`, выборки для отчётов и метрик. `AgentSettings::traceRetentionDays`,
  `Config`/`MetricsSettings::token()`.
- [ ] Контракт хранилища (память + PostgreSQL), тесты настроек → коммит `feat(db): store trace spans and payloads`.

### Task 2: События и `Tracer`

- `AgentEvents`: `runStarted(Run)`, `modelCalled(Run, ChatRequest, ?ChatResponse, ?string $error, float $seconds, string $purpose)`,
  `toolFinished(Run, string $name, array $args, ToolResult, float $seconds, string $status)`, `approvalDecided(Run, string $tool, string $outcome, float $seconds)`,
  `compacted(Run, bool $stub, float $seconds)`, `runFinished(Run)`. `NullEvents` по умолчанию.
- `Tracer implements AgentEvents`; стоимость — из `usage.costUsd` или по каталогу.
- Цикл, `ContextCompactor`, `RequestClassifier`, `ApprovalService` сообщают события.
