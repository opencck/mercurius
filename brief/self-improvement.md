# Спецификация: самоулучшение

## Самоулучшение

Решение владельца 2026-11-18: агент предлагает, владелец утверждает; бюджет — прогон набора задач по нажатию
владельца и еженедельный разбор трасс заданием.

- **Оценка фактов по использованию и фоновое предложение фактов** — сделаны 2026-11-18, устройство — в
  [Фактах](memory.md#факты).

### Границы

Решено владельцем 2026-11-16.

| Что меняется | Агент сам | Через владельца |
|--------------|-----------|-----------------|
| Новые факты, в том числе о третьих лицах | Да, с происхождением и доверием | — |
| Исправление и забывание фактов | По прямой просьбе владельца в разговоре | По собственной инициативе — предложением |
| Слой «всегда в контексте» | Добавление | Правка и удаление — очередь одобрения |
| Ядро: личность, правила, политика подтверждений, лимиты, набор инструментов | Нет | Только владелец; агент может предложить |
| Таблица выбора моделей и веса «цена — скорость — качество» | Да, подстраивает по контексту и трассам, с записью причины | Владелец может зафиксировать значения |
| Роли участников (людей и агентов), права доступа | Только если владелец делегировал агенту это право (см. [участники](participants.md#участники-люди-и-агенты)) | Владелец определяет принципы распределения прав; роль владельца не меняется |
| Новый скилл, правка скилла | В папке участника или проекта (решение владельца 2026-11-18): проверка `SkillGuard` при записи и при каждом чтении (описание для индекса, каждый файл), снимок рабочего каталога перед записью | Встроенные — только через код (сабмодуль) |
| Выученные разрешения на действия | Нет | Владелец отвечает «разрешать всегда» на карточке подтверждения |
| Собственный код Меркурия | **Только когда разработка Меркурия — порученная ему задача**, как любой другой проект | Сам себя по ходу работы не дорабатывает |

- **Доработка — отдельно и другим агентом.** Агент работает так, чтобы в логах и трассах оставалось всё, что нужно для его доработки: решения и их причины, выбор моделей, ошибки, расход, отказы и неудачи, предложения по улучшению. Разбирает эти данные и дорабатывает Меркурий другой агент (или Меркурий, которому это поручили как задачу разработки).
- Всё, что агент меняет сам, версионируется и откатывается; ядро и скиллы недоступны общим инструментам записи файлов.

### Разбор трасс

**Разбор трасс** — инструмент `trace_review` (только владелец, недоверенный результат): за 1–30 дней остановки
запусков по причинам, инструменты — вызовы, ошибки, отказы и последняя ошибка, вызовы того же инструмента после
отказа в том же запуске (проверка безопасности, не только расхода), самые дорогие запуски, расход по назначениям.
Образец — `insights.py` hermes. С 2026-11-20 разбор, поиск по истории и список запусков не видят канал `eval`:
прогон ворот самоулучшения не меняет статистику разбора (деньги в `/spending` его по-прежнему считают).
Правила (по ревью сессий cookbooks, `CMA_agent_security_review`): вызовы, которые не разрешила политика
участника (флаг `tool_calls.refused`, миграция 79), и действие наружу в ближайших шести вызовах после отказа
владельца (`retry-after-refusal`). Правила хостов и секретов против «гранта» cookbooks не перенесены: грант у
Меркурия — политика участника и сохранённые разрешения, их нарушение отсекает сам цикл до вызова.

### Задание self-review

**Задание `self-review`** по `SELF_REVIEW_SCHEDULE` (по умолчанию `weekly:sun@20:00`; пусто — выключено): разбор
недели и не больше двух предложений с основаниями; ничего заметного — `[SILENT]`. Инструменты — только белый список
(`JobScheduler::SELF_REVIEW_TOOLS`: разбор трасс, расход, о себе, поиск по истории, опыту и памяти, чтение скиллов,
предложение изменения). Работает как любое задание:
тихие часы, лимит токенов задания, потолок инициативы в сутки.

### Предложения

**Предложение** — инструмент `improvement_propose` (только владелец и его задания): `prompt` — полный новый текст
заметок к системному промпту; `setting` — значение настройки (не секретной, с проверкой значения); `idea` — всё
прочее (код, инструменты, права) для того, кто дорабатывает Меркурий. Секреты и невидимые символы в предложении
отвергаются. Владельцу — карточка «Принять / Отклонить» (`im:`), таблица `improvements` (миграция 50).
`/proposals` — показать нерешённые предложения карточками заново (если карточка затерялась в ленте).

**Настройка** включается по «Принять» через `SettingsService` (действует после перезапуска); **идея** — только
записывается.

### Заметки к промпту

**Заметки к промпту** — версии в `prompt_notes`: версия не меняется, действующая — указатель (одна строка с
`active`). Заметки идут сразу после постоянных правил в промпт каждой новой беседы. `/prompt` — версии,
`/prompt rollback <версия>` — вернуть прежнюю, `/prompt off` — базовый промпт. Оценки по категориям (решение
В7 — только хранение и отчёт): ворота пишут средние, ошибку и число прогонов каждой категории для текущих заметок и
кандидата в `eval_scores` (миграция 80; версия — хеш текста заметок), `/prompt scores` сравнивает две последние
проверенные версии по категориям; версия с известным текстом называется `vN`. Попарного сравнения, расширения набора
и ворот для настроек нет.

### Ворота изменения промпта

**Ворота изменения промпта.** «Принять» у `prompt` в фоне прогоняет набор проверочных задач (`src/App/Eval`,
`resources/eval/tasks.json`: 22 задачи, 9 категорий) для текущих заметок и кандидата: та же модель (`LLM_MODEL`),
судья другой семьи (`EVAL_JUDGE_MODEL`, по умолчанию `claude-haiku-5.5`), `EVAL_RUNS` прогонов (не меньше 3),
по 4 задачи одновременно, каждая — в своей беседе канала `eval`. Кандидат включается, только если ни одна категория
не стала хуже сверх шума (`EvalReport::regressions`); владелец получает отчёт по категориям. Без судьи, с меньше
чем 20 задачами или 3 прогонами — проверки нет, изменение не включается. Расход прогона — обычные `llm_calls`.
Перезапуск посреди проверки: при старте предложение из `checking` возвращается в `proposed`, владелец получает
сообщение и карточку снова. Отклонённое не повторяется дословно: `improvement_propose` с заголовком, совпадающим с
недавно отклонённым (без учёта регистра и пробелов), получает отказ со списком последних отклонённых.

### Самоизменение с разрешением навсегда

Самоизменение (заметки к промпту, настройки, роли моделей, скиллы) владелец может разрешить навсегда; тем же
разрешением он может отключить ворота набора задач.
Сделано: на карточке улучшения — кнопка «Разрешать всегда» (`im:<номер>:g`), разрешение
`self-improve:<вид>` хранится среди разрешений владельца (`/permissions`, отзывается там же); следующее предложение
того же вида применяется само, владельцу — уведомление. Проверку изменения промпта набором задач выключает
настройка `IMPROVE_GATE=0`.
