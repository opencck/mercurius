### Принятые владельцем риски

- **Сеть песочницы открыта.** Команда в песочнице может отправить данные наружу без карточки; подтверждаются
  распознанные действия наружу и всё, что идёт с секретом.
- **Браузер без подтверждений по умолчанию** — нажатия, ввод, отправка форм, в том числе у не-владельцев и в запусках
  с пометкой внешних данных. Настройка `BROWSER_CONFIRM` включает подтверждения. Сделано: `BROWSER_CONFIRM=0` по
  умолчанию — `click` и `type` с `submit` идут как запись, без карточки; `1` — карточкой. Внутренний адрес и
  скрипт, действующий на живой странице, по-прежнему ждут карточки.
  Сделано: `type` пишет только в поле ввода (`input` текстовых видов, `textarea`, `contenteditable`), ставит фокус
  без щелчка и вставляет текст как текст — перевод строки не нажимает Enter; отправка — только явным `submit` или
  `click`.
- **Импорт скиллов** блокирует только находки уровня `critical`.
- **Файлы памяти, скиллов и промптов** доступны общим инструментам записи.
- **Денежных лимитов по умолчанию нет;** владелец задаёт любой.
- **Боты в группах слушаются** — с правами посетителя и обязательной защитой от петель; участник может назвать, кого
  игнорировать.
- **Правила `MEMORY.md` места пишет любой с доступом к месту** (2026-11-21): правило одного участника или внешнего
  агента действует для всех там — [правила и заметки](memory.md#правила-и-заметки-memorymd).
- **Секреты проходят через песочницу** (2026-11-25): секрет, отнесённый к MCP, получает процесс MCP в песочнице —
  рядом с командами модели. Прежнее «секреты в песочницу не попадают» отменено. Защита — отдельный пользователь Unix
  на MCP, одобрение записи с её секретами по хешу, наследование широких слоёв только по включению, скрытие чужих
  процессов
  ([подстановка секретов](skills-mcp.md#подстановка-секретов)).
- **Закрытый ключ SSH читается внутри песочницы** (2026-11-25): в `~/.ssh` кладут ключ с ограниченными правами
  ([ключи SSH в песочнице](servers.md#ключи-ssh-в-песочнице)).
- **Секрет, отданный чужому MCP, может уйти куда угодно** (2026-11-25): владелец сам решает, какому MCP что дать.

Аудит безопасности 2026-11-18 закрыт; его итог и принятые риски — в [истории](history.md#аудит-безопасности-2026-11-18).

### Продукт и архитектура

- **Orchestrator-workers закладывается с первой версии** — решение владельца. Изученные источники советуют начинать с
  одного агента ([вывод 1](knowledge.md#ключевые-выводы)), поэтому делегирование — возможность, которую агент выбирает
  сам, а не обязательный путь.
- **Ядро строится по аналогии с hermes-agent**, память — по принципам hermes-plugin-holographic и hermes-dreaming.
  Переносим принципы и проверенные решения, а не код: у hermes Python и SQLite, у нас PHP и PostgreSQL.
- **Первый провайдер модели — OpenRouter.** Интерфейс провайдера унифицирован, другие провайдеры добавляются адаптерами.
- **Ключ OpenAI через OpenRouter (BYOK)** (решение владельца 2026-11-16): для моделей, доступных агенту, ключ OpenAI
  используется напрямую через OpenAI API. Возможность пустить ключ OpenAI через OpenRouter остаётся — например, для
  ключа, который прислал пользователь: OpenRouter принимает чужой ключ провайдера только в настройках аккаунта (BYOK,
  раздел интеграций или его API), а не в запросе, поэтому это — инструмент агента, который регистрирует ключ в аккаунте
  OpenRouter (изменение настроек аккаунта — через подтверждение владельца; ключ — из хранилища секретов).
- **Второй провайдер — OpenAI API** (решение владельца 2026-11-16): ключ `OPENAI_API_KEY`; запросы идут через VLESS,
  если задан `VLESS_URI`, как у OpenRouter. Агенту нужна хотя бы одна модель одного провайдера: может быть задан только
  ключ OpenRouter или только ключ OpenAI — приложение работает с тем, что есть.
- **Первый канал связи — Telegram-бот.** Интерфейс канала унифицирован; владелец определяется по `TELEGRAM_ADMIN_ID`.
- **СУБД — только PostgreSQL**: памяти нужны полнотекстовый поиск, массивы и JSON-поля, векторы — через `pgvector`;
  запросы пишутся под PostgreSQL. MariaDB не поддерживается (решение 2026-11-18, доработки).
- **Политика команд — «запрещено, пока не доказано чтение».** Командой чтения считается только та, что есть в списке и
  чьи аргументы прошли проверку; всё нераспознанное требует подтверждения. У образца (`ssh-mcp`) порядок обратный, и его
  авторы сами показывают, чем это кончается ([конспект](../docs/notes/ssh-mcp.md)).
- **Выбор моделей под задачу по профилю из оценок 1–10** — требование владельца; проект устройства — [«Выбор моделей под задачу»](models.md#выбор-моделей-под-задачу). Модель основного диалога
  меняется только на границе сессии.
- **Telegram — через webhook** за Nginx Proxy Manager: сервис в внешней Docker-сети `web`, вход `https://<домен
  агента>/`, проверка `X-Telegram-Bot-Api-Secret-Token`; при пустом `APP_URL` — long polling.
- **Экземпляры Меркурия объединяются в сеть агентов по WebSocket API**; удалённый агент — разновидность воркера, под
  политикой своего владельца; у каждого подключающегося агента свой токен — см. [«Сеть
  агентов»](network.md#сеть-агентов).
- **Изоляция, самоулучшение, пользователи** — решения владельца ниже: [изоляция
  исполнения](agent-loop.md#изоляция-исполнения), [границы самоулучшения](self-improvement.md#границы), [участники: люди
  и агенты](participants.md#участники-люди-и-агенты).
- **Память: слой «всегда в контексте» и HRR делаются сразу** (решение владельца 2026-11-16) — см. [«Память:
  слои»](memory.md#память-слои).
- **Маршрут к модели:** при заданном `VLESS_URI` запросы к провайдерам моделей идут через VLESS, при пустом — напрямую;
  в `.env` для тестирования задан рабочий URI, в `.env.example` переменная пустая.
- **`hermes-dreaming` — репозиторий `itpartypattaya`** (подтверждено владельцем).
- **Подтверждение — приостановленный вызов инструмента**, а не инструкция в промпте: проверка стоит в самом инструменте,
  идентификатор вызова служит токеном возобновления.
